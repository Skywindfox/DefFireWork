# FireControlApp

**智能楼宇消防系统**的控制端软件 —— 省级大学生创新创业训练计划项目（两人合作）。

运行在 STM32MP135（正点原子 ATK-DLMP135）开发板上：自编译的 Debian 12、1024×600 触摸屏，
用 C++ 与 LVGL 写界面，直接驱动现场设备。

> 本仓库仅作个人存储，不建议对外直接使用。

---

## 项目目的

把楼宇消防里"**感知 → 判断 → 报警 / 联动**"这条链路，做成一套**装在楼内本地、断网也能独立运行**
的控制系统：

- **感知**：把分布在楼内的消防状态量（各类开关量传感器、按键）接进控制器，持续采集。
- **判断**：在本地按预设规则判定火警与故障，不依赖云端的往返时延。
- **报警 / 联动**：驱动声光报警、指示与设备联动，并让人在触摸屏上直接看到状态、手动干预。

现在的楼宇消防大多靠孤立的独立式探测器加人工巡检：信息不汇总、报警靠现场喇叭与电话，
控制器与值班界面往往是成套采购的封闭设备。这个项目想验证的是 ——
**一块低成本的嵌入式板卡能不能承担同样的事**。

---

## 项目意义

- **工程上**：用通用 Linux + 开源图形库替代封闭的消防控制器方案，成本与二次开发门槛都低得多；
  业务逻辑与界面都是普通代码，改起来不必等厂商。
- **部署上**：本地闭环、离线可用。断网、断电恢复后仍需独立报警，这是消防场景的底线要求。
- **教学与团队上**：覆盖"硬件平台 → 系统移植 → 驱动接口 → 应用与界面"的完整链路，
  是一个从底层到应用都要自己动手的综合课题。

## 要完成的任务

| 任务 | 内容 | 进度 |
|---|---|---|
| 硬件平台与系统 | 开发板硬件验证、用自编译的 Debian 替换原系统、显示 / 触摸 / 桌面环境就绪 | 100% |
| 传感器 | 消防状态量接入与采集（GPIO 开关量） | 0% |
| 触发器与联动 | 报警判定规则、声光报警与设备联动 | 0% |
| PCB | 自绘控制板 | 0% |
| 中控软件 | 设备控制、状态采集、可控的运行骨架 | 5% |
| 人机界面 | 触摸屏界面与可视化 | 结构已完成，美化 0% |

**近期目标**：把已接通的板载 LED、蜂鸣器与外部无源蜂鸣器纳入统一的报警联动，
补上传感器采集，在板上跑通一次完整的"传感器触发 → 判定 → 声光报警"闭环。
